# 2026-10-23 CI 게이트 정직성 보수

## 문제

이전 `.github/workflows/pluginval.yml`의 macOS job은 `cmake -B Build
-DCMAKE_BUILD_TYPE=Release && cmake --build Build --config Release`로 빌드한 뒤
`./scripts/run_pluginval.sh`만 실행했다. 저장소의 실제 회귀 게이트인 CTest
5개(`CMakeLists.txt`의 `add_test`)는 CI에서 한 번도 돌지 않았으므로, 로컬
`ctest`가 빨간 상태여도 CI는 초록으로 통과할 수 있었다. pluginval은 VST3 로드와
파라미터 자동화를 보지만 preset/오디오 스모크, 실시간 계약, DSP 수치, 파형
하모닉, MIDI 계약은 검사하지 않는다.

## 지금 CI가 하는 일

`macos` job(`macos-14`)은 다음 순서로 진행한다.

1. `Configure` — `cmake -B Build -DCMAKE_BUILD_TYPE=Release`
2. `Build` — `cmake --build Build --config Release --parallel`
3. `CTest` — `ctest --test-dir Build -C Release --output-on-failure`
   (`set -o pipefail` + `tee Build/ci-logs/ctest.log`)
4. `Install pluginval` — `brew install --cask pluginval`
5. `Validate VST3` — `./scripts/run_pluginval.sh` (strictness 5 유지,
   `tee Build/ci-logs/pluginval.log`)
6. `Upload validation logs` — `actions/upload-artifact@v4`,
   `if: always()`라서 3·5단계가 실패해도 두 로그가 아티팩트로 남는다
   (`Build/ci-logs/*.log`, `Build/**/pluginval*.log`)

`dsp-sanity` job(`ubuntu-latest`, `python3 scripts/run_dsp_sanity.py`)은 그대로
둔다. 즉 DSP 수치 검사는 Ubuntu와 macOS CTest 양쪽에서 돈다. 새로 추가한
action은 없고 `actions/checkout@v4`와 `actions/upload-artifact@v4`만 쓴다.
시크릿은 쓰지 않는다. 네트워크를 타는 단계는 이전과 같은
`brew install --cask pluginval` 하나뿐이다.

CTest 항목은 5개다: `preset_state_and_audio_smoke`,
`realtime_audio_contract`, `dsp_numeric_sanity`,
`wave_harmonic_baseline`, `midi_contract`. `dsp_numeric_sanity`는
`Python3_Interpreter_FOUND`일 때만 등록되므로, Python이 없는 환경에서는
4개만 돈다(로컬 `ctest -N` 기준 5개).

## 로컬에서 각 게이트를 증명하는 명령

```sh
# DSP 수치 스모크 (Ubuntu job과 같은 명령)
python3 scripts/run_dsp_sanity.py

# 빌드 + CTest 5개 (macOS job의 3단계와 같은 명령)
cmake -B Build -DCMAKE_BUILD_TYPE=Release
cmake --build Build --config Release --parallel
ctest --test-dir Build -C Release --output-on-failure

# VST3 형식 검증 (strictness 5)
PLUGINVAL_BIN=/path/to/pluginval ./scripts/run_pluginval.sh
```

이번 작업 시점의 로컬 실행 결과는 `ctest --test-dir Build -C Release` 기준
5/5 통과, 총 16.57초였다.

## 남은 구멍

- **AU 검증은 CI에 없다.** `CMakeLists.txt`는 `FORMATS AU VST3 Standalone`으로
  AU를 빌드하지만 워크플로는 VST3만 pluginval에 넘긴다. AU는 로컬에서
  `auval -v aumu MnEf EEFL`로 따로 확인해야 한다. 같은 작업에서 제조사
  코드가 EonA에서 EEFL로 바뀌었으므로 이전 문서의 EonA 명령은 더 이상
  맞지 않는다.
- **호스트 로드·offline bounce는 여전히 수동이다.** Cubase/Ableton Live/Logic
  에서 preset 저장·복원과 bounce 일치 확인은 자동화되어 있지 않다.
- **REAPER는 쓰지 않는다.** `Mini EEF/AGENTS.md` 규칙에 따라 기본 검증 경로가
  아니며, 실행이 필요하면 먼저 사용자에게 확인한다.
- CTest는 오디오 콜백을 헤드리스로 두들기는 수준이고, 실제 DAW 스케줄링이나
  GUI 상호작용은 다루지 않는다.
